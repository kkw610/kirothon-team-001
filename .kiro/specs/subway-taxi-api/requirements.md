# 요구사항: 지하철·택시(카카오모빌리티) 외부 API 연동

담당 브랜치: `feat/api` (base: `develop`)
관련 steering: `product.md`, `tech.md`, `structure.md`, `domain-rules.md`, `workflow.md`
인계 문서(데이터 계약): `handoff.md`

## 배경
`transit`과 `taxi` 기능은 가짜 데이터로 동작했다. 데모(로컬호스트 `http://localhost:3000`)에서 실제 경로, 소요 시간, 요금으로 추천이 나오도록 두 기능의 `service.ts` 내부를 실제 API로 교체한다.

출발 시각에 따라 지하철 경로와 환승이 달라지므로, 지하철 경로도 출발 시각을 기준으로 찾아야 한다(개정 2). 결정 과정은 `design.md`의 "결정 기록"에 있다.

## 변경 이력
- 개정 4: 지하철+도보 경로를 기준으로 두고 택시 환승과 비교할 수 있도록 도보 구간(R1.14)을 추가. 추천 로직 변경은 `design.md` D4와 공통 파일 변경 요청 9~11.
- 개정 1: 역별 거리·요금, 택시 동시병산·심야 할증·미래 교통 예측 추가.
- 개정 3: TMAP 실제 응답 확인 결과 반영. `searchDttm`은 경로와 소요시간을 바꾸지 않고 운행 여부(`service`)만 준다(R1.10). 무료 한도 일 10건(R3.6).
- 개정 2: 출발 시각 기준 경로(R1.10, R1.11), 대체 경로(R1.12), 1~9호선 제한(R1.13) 추가. 지하철 API를 ODsay에서 TMAP 대중교통으로 교체(`design.md` D1~D3).

## 요구사항

### R1. 지하철 경로 조회
- R1.1 `getTransitRoutes(origin, destination, departureAt?, options?)`는 TMAP 대중교통(`POST https://apis.openapi.sk.com/transit/routes`)을 호출한다. 키는 `TRANSIT_API_KEY`다.
- R1.2 응답 경로 중 지하철과 도보만으로 이루어진 경로를 응답 순서대로 고른다. 기본은 1개다(`domain-rules.md`: 지하철 단일 경로, 경로 1개).
- R1.3 `Route.stops`는 경로가 지나는 모든 지하철역을 순서대로 담는다. 각 `Stop`은 역 이름, 경도(x), 위도(y), 출발지부터의 누적 소요시간(`elapsedMin`), `mode: "subway"`를 가진다.
- R1.4 API가 역별 소요시간을 주지 않으므로, 구간 소요시간을 구간 안 역 사이 직선거리 비율로 나눠 `elapsedMin`을 계산한다. 도보 구간 시간도 누적에 포함한다.
- R1.5 환승역처럼 같은 역이 연속으로 두 번 나오면 먼저 나온 것 하나만 남긴다.
- R1.6 `Route.fare`는 API 응답의 경로 전체 요금을 쓴다.
- R1.7 같은 출발지, 목적지, 출발 시각(10분 단위) 조합은 10분간 캐시한다(TMAP 일 10건 한도).
- R1.8 각 `Stop`에 노선 이름(`line`), 탑승역부터 누적 거리(`distanceM`), 그 역에서 내릴 때의 지하철 요금(`fare`)을 담는다. 요금은 수도권 지하철 거리비례 운임(성인 카드)으로 계산하고 경로 전체 요금을 넘지 않게 한다.
- R1.9 `Route`에 총 소요시간(`totalMin`)과 환승 횟수(`transferCount`)를 담는다.
- R1.10 TMAP 호출 시 `departureAt`(생략 시 현재 시각)을 `searchDttm`(Asia/Seoul `yyyyMMddHHmm`)으로 보낸다. 응답의 구간별 `service`가 0(그 시각 미운행)인 지하철 구간이 있는 경로는 뺀다. 모든 후보가 미운행이면 `NO_ROUTE`("출발 시각에 운행하는 지하철 경로가 없습니다")다.
- R1.11 `Route.timeAware`에 출발 시각 반영 여부를 담는다.
- R1.12 `options.maxRoutes`(1~3, 기본 1)를 주면 추천 경로 뒤에 대체 경로를 붙인다. `routes[0]`이 추천 경로다(`design.md` D2).
- R1.13 모든 지하철 구간이 수도권 1~9호선(급행 포함)인 경로만 쓴다. 다른 노선(신분당선, 경의중앙선, 공항철도 등)이 섞인 경로는 제외하고, 남는 경로가 없으면 `NO_ROUTE`다.

- R1.14 `Route`에 출발지→첫 역 도보(`walkFromOrigin`)와 마지막 역→목적지 도보(`walkToDestination`)를 담는다. 각각 거리(m)와 시간(분)이고, TMAP 응답의 첫·마지막 `WALK` 구간 값을 쓴다. 추가 API 호출은 하지 않는다. 환승 도보는 `elapsedMin`에 이미 포함된다.
- R1.15 `Route.totalMin`은 택시 없이 지하철과 도보로만 목적지까지 가는 시간이다. 추천 로직은 이 값과 `Route.fare`로 "택시 없음" 기준 옵션을 만들 수 있어야 한다.

### R2. 택시 거리와 시간 조회 (카카오모빌리티)
- R2.1 `estimateTaxi(from, to, boardingAt?)`는 카카오모빌리티 자동차 길찾기를 `summary=false`로 호출해 거리(m), 소요시간(초), 도로 구간별 거리와 시간을 얻는다.
- R2.2 응답의 요금 값(`fare.taxi`)은 쓰지 않는다. 요금은 `calculateTaxiFare({ distanceM, slowSec, boardingAt })`로 계산한다. (`domain-rules.md`)
- R2.3 후보 역이 많으므로 동시 호출 수를 제한하고(최대 5), 같은 좌표쌍과 출발 시각은 캐시와 진행 중 요청 공유로 한 번만 호출한다.
- R2.4 `calculateTaxiFare`는 서울시 중형택시 요금표로 계산한다. 출처를 주석으로 남기고 경계값 단위 테스트를 둔다.
- R2.5 시속 15.72km 미만 구간은 시간요금과 거리요금을 동시에 센다(동시병산).
- R2.6 택시 탑승 시각(Asia/Seoul)에 따라 심야 할증(20%, 40%) 요금표를 적용한다.
- R2.7 탑승 시각이 5분보다 뒤면 그 시각의 교통 예측(카카오 미래 길찾기)으로 거리와 시간을 구한다.

### R3. 공통 동작
- R3.1 API 키(`TRANSIT_API_KEY`, `KAKAO_REST_API_KEY`)는 서버에서만 읽고, 로그와 응답에 남기지 않는다.
- R3.2 모든 외부 호출에 타임아웃(5초)을 둔다.
- R3.3 외부 API 응답 형식은 기능 폴더 밖으로 새지 않는다. `shared/types.ts`의 타입으로 변환해 내보낸다.
- R3.4 실패는 원인을 구분하는 오류(경로 없음 / 외부 API 오류 / 설정 누락)로 던진다. 추측 값으로 대체하지 않는다.
- R3.6 TMAP 대중교통 무료 한도는 **일 10건**이다(초과 시 차단). 추천 요청당 1회만 호출하고, 같은 출발지·목적지·출발 시각(분)은 캐시한다.
- R3.5 외부 응답 변환(TMAP, 카카오 파싱)과 역별 값 계산(`buildRoute`)은 순수 함수로 분리하고 샘플 응답으로 단위 테스트한다.

## 범위 밖
- 장소 검색(`places`, Kakao Local)은 다른 담당자가 한다.
- 시계외 할증, 통행료, 조조할인, 청소년 요금.
- 서울 밖 출발지와 목적지 안내(`domain-rules.md`). 위치는 `app/api/recommend/route.ts`가 적절하며 공통 파일 변경 요청에 적는다.
- 실시간 열차 지연 반영, 택시 호출, 결제, 지도 표시.
