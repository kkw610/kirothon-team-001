# 택시 환승역 추천

약속에 늦을 것 같을 때, 지하철을 타다가 어느 역에서 택시로 갈아타야 제시간에 가장 싸게 도착하는지 계산해 주는 웹 서비스.

**Demo:** https://youtu.be/YFdfiA_hT9c

---

## 1. 문제 정의

### 대상 사용자

약속에 자주 늦어서 지하철로 이동하다가 중간에 택시로 갈아탄 경험이 있는 서울 수도권 이용자.

### 문제 상황

- 상황: 지하철로 이동하는 중에 약속 시각에 늦을 것 같다는 걸 알게 된다.
- 불편 1: 일찍 내릴수록 택시비가 늘고 늦게 내릴수록 도착이 늦어지는데, 그 사이에서 비용이 가장 적은 역을 직접 계산해야 한다.
- 불편 2: 어느 역에서 내려야 제시간에 도착하는지 알 수 없다.
- 불편 3: 이 계산을 지하철 경로 앱과 택시 앱을 오가며 매번 손으로 한다.

### 기존 방식과 한계

지도 앱은 대중교통 경로와 택시 경로를 따로만 보여 준다. 두 수단을 섞은 경로, 즉 "몇 번째 역에서 내려 택시를 타면 총비용이 얼마인지"는 보여 주지 않는다. 사용자가 후보 역마다 지하철 시간, 택시 시간, 요금을 직접 더해 비교해야 한다.

### 근거

- 팀원이 약속에 자주 늦어 지하철 이동 중 택시로 갈아타는 일이 많고, 그때마다 위 계산을 직접 한다(팀 내 경험).

### 목표

출발지, 목적지, 도착해야 하는 시각을 입력하면 제시간에 도착하는 방법 중 총비용이 가장 적은 택시 환승역 하나를 추천해서, 사용자가 직접 계산하지 않게 한다.

## 2. 핵심 기능

| 기능                           | 해결하는 불편                                                    | 코드 위치                     |
| ------------------------------ | ---------------------------------------------------------------- | ----------------------------- |
| 출발지, 목적지, 도착 시각 입력 | 계산에 필요한 정보를 한 번에 입력 (불편 3)                       | `src/features/search-form/` |
| 장소 검색                      | 이름으로 장소를 찾아 좌표로 변환                                 | `src/features/places/`      |
| 지하철 경로 조회               | 경로상의 역과 역까지의 소요 시간 확인 (불편 1)                   | `src/features/transit/`     |
| 택시 거리, 시간, 요금 계산     | 역에서 목적지까지 택시로 가는 시간과 요금 확인 (불편 2)          | `src/features/taxi/`        |
| 환승역 추천                    | 제시간에 도착하는 후보 중 총비용이 가장 낮은 역 선택 (불편 1, 2) | `src/features/recommender/` |
| 추천 결과 화면                 | 지하철 시간, 택시 시간, 택시비, 도착 시각, 총비용 표시           | `src/features/result/`      |
| 지도 표시                      | 경로와 추천 환승역 위치 표시                                     | `src/features/map/`         |

### 추천 규칙

- 도착 시각 = 출발 시각 + 환승역까지 지하철 시간 + 택시 대기 3분 + 택시 이동 시간
- 총비용 = 지하철 요금 + 택시 요금
- 도착 시각이 희망 시각 이하인 후보 중 총비용이 가장 낮은 역을 추천한다. 비용이 같으면 도착이 더 빠른 역을 고른다.
- 제시간 도착이 불가능하면 추천 없이 가장 빨리 도착하는 대안을 보여 준다.
- 범위는 서울 지하철 단일 경로로 한정한다. 택시 대기 시간은 3분으로 고정하고, 택시 요금은 외부 API 값이 아니라 거리와 시간으로 직접 계산한다.

자세한 규칙은 `.kiro/steering/domain-rules.md`에 있다.

## 3. 사용 시나리오

1. 사용자가 출발지(예: 신촌역), 목적지(예: 강남역), 도착해야 하는 시각을 입력한다.
2. 서버가 지하철 경로를 조회하고, 경로상의 각 역에서 목적지까지 택시로 가는 거리와 시간을 구한다. 택시 요금은 거리와 시간으로 계산한다.
3. 화면에 추천 환승역 하나와 근거가 나온다. 근거는 지하철 몇 분, 택시 몇 분, 택시비, 도착 시각, 총비용이다.
4. 사용자는 전체 후보 역의 비교 표와 지도를 보고, 해당 역에서 내려 택시를 탄다.

## 4. 기대 효과

- 환승역 결정에 드는 시간: 후보 역마다 앱 두 개를 오가며 직접 계산 → 입력 한 번으로 끝.
- 추천 결과는 총비용 기준으로 후보 중 최저다. 전 구간 택시와 비교한 절감 금액을 데모 시나리오로 측정해 적는다.

## 5. 차별점

|                 | 기존 지도 앱        | 이 서비스                                     |
| --------------- | ------------------- | --------------------------------------------- |
| 대중교통과 택시 | 경로를 따로 보여 줌 | 지하철 구간과 택시 구간을 합친 경로를 계산    |
| 환승역 선택     | 사용자가 직접 비교  | 도착 시각 조건을 만족하는 최저 비용 역을 추천 |
| 비용            | 수단별 요금만 표시  | 지하철 요금 + 택시 요금의 총비용 비교         |

## 6. 설치와 실행

요구사항: Node.js, npm

```bash
# 1. 의존성 설치
npm install

# 2. 환경변수 설정 (가짜 데이터 단계에서는 값이 비어 있어도 실행된다)
cp .env.example .env.local
# .env.local에 KAKAO_REST_API_KEY, KAKAO_JS_KEY, TRANSIT_API_KEY를 채운다. 커밋하지 않는다.

# 3. 개발 서버 실행
npm run dev
# http://localhost:3000
```

### 프로젝트 구조

```
app/                 페이지와 API 라우트 (GET /api/places, POST /api/recommend)
src/features/        기능별 폴더: places, transit, taxi, recommender, map, result, search-form
src/shared/          공통 타입, 서버 전용 환경변수, 메모리 캐시
.kiro/steering/      product, tech, domain-rules, structure 문서
```

기능 폴더끼리는 서로 import하지 않고 `src/shared/types.ts`의 타입으로만 데이터를 주고받는다. 자세한 규칙은 `.kiro/steering/structure.md`를 본다.

## 7. 테스트

```bash
npm test          # 추천 알고리즘, 택시 요금 계산 단위 테스트 (Vitest)
npm run lint      # ESLint (기능 폴더 간 import 금지 규칙 포함)
npm run typecheck # 타입 검사
npm run build     # 프로덕션 빌드
```
